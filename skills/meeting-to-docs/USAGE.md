# Использование `meeting-to-docs`

Этот файл предназначен для пользователей скилла. Внутренний рабочий процесс агента описан в `SKILL.md`.

## Установка

Ссылка на GitHub — это источник для установки, а не удалённый исполняемый скилл. Codex загружает отдельные скиллы из локальных директорий или из директории текущего репозитория. Поэтому скилл нужно установить на каждом устройстве, где вы хотите им пользоваться.

### Рекомендуемый способ: установка из GitHub через Codex

Вызовите встроенный установщик и передайте ему ссылку на директорию скилла:

```text
$skill-installer
Установи скилл из https://github.com/UnidentifiedRaccoon/work-skills/tree/main/skills/meeting-to-docs
```

Установщик поместит скилл в `$CODEX_HOME/skills` (обычно `~/.codex/skills`). Он станет доступен со следующего хода. Если скилл не появился в списке, перезапустите Codex.

### Ручная установка для пользователя

Скопируйте всю директорию `meeting-to-docs` или создайте на неё символическую ссылку в:

```text
$HOME/.agents/skills/meeting-to-docs
```

Такой скилл будет доступен во всех репозиториях на этом устройстве. Важно сохранить директорию целиком: `SKILL.md`, `agents/` и `references/` используются совместно.

Встроенный установщик самостоятельно управляет директорией `$CODEX_HOME/skills`, поэтому при обычной установке лучше использовать его. `$HOME/.agents/skills` — стандартное место обнаружения отдельных скиллов, установленных вручную для текущего пользователя.

### Установка только для одного репозитория

Чтобы скилл был доступен только внутри конкретного репозитория, скопируйте его в:

```text
<repository>/.agents/skills/meeting-to-docs
```

Если одна и та же версия нужна всей команде, добавьте эту директорию в репозиторий.

### Использование на другом устройстве и «удалённый скилл»

Для личного использования на нескольких устройствах достаточно установить скилл из этого GitHub-репозитория на каждом из них. При каждом запуске `SKILL.md` не загружается с GitHub заново: Codex использует установленную локальную копию.

Если потребуется распространять скилл другим людям в один клик или использовать его на разных поверхностях ChatGPT, его следует упаковать как плагин. Плагин — это устанавливаемый способ распространения; после установки сам скилл всё равно работает локально.

Актуальные директории и способы распространения описаны в [документации OpenAI по скиллам](https://developers.openai.com/codex/skills).

## Запуск

Самый предсказуемый способ — вызвать скилл явно:

```text
$meeting-to-docs

Подготовь transcription.md и summary.md по приложенной записи встречи.
Также используй приложенную схему, спецификацию и ссылки на сервисы.
Суммаризацию напиши на русском языке. Транскрибация должна быть
читабельной, а не дословной. Сохрани оба файла в <директория результата>.
```

Список участников можно не передавать. Если имена и роли известны, их полезно указать, но восстанавливать состав встречи до запуска необязательно. Скилл попытается определить участников самостоятельно и только после подготовки черновиков задаст один общий уточняющий вопрос, если личности говорящих останутся неясны.

По возможности приложите:

- основную аудио- или видеозапись, субтитры либо существующую черновую транскрибацию;
- связанные файлы, схемы, скриншоты, ссылки и документы;
- дату и тему встречи;
- директорию результата и желаемый язык;
- требование к транскрибации: читабельная или строго дословная;
- известные имена участников и их предполагаемые роли.

Неявный запуск тоже работает, если запрос явно требует транскрибацию встречи с таймкодами и переиспользуемую техническую суммаризацию. Однако явное указание `$meeting-to-docs` снижает неоднозначность.

## Требования к работе с аудио и видео

Скилл содержит инструкции и правила проверки, но не включает собственный движок распознавания речи. Запускайте его в среде, которая умеет читать приложенную запись или предоставляет субтитры, транскрибацию либо инструмент распознавания речи.

Если среда не может обработать запись, передайте готовую транскрибацию или субтитры. Скилл не должен придумывать отсутствующую речь.

## Рекомендуемая модель и effort

Актуальная базовая рекомендация на август 2026 года:

| Конфигурация | Когда использовать | Рекомендация |
|---|---|---|
| `gpt-5.6-sol`, `high` | Финальная транскрибация и техническая документация по нескольким источникам | Рекомендуемый вариант по умолчанию, когда важнее качество. |
| `gpt-5.6-terra`, `high` | Обычные встречи, где важны стоимость и скорость | Сбалансированный вариант; особенно внимательно проверьте соответствие голосов участникам и технические термины. |
| `gpt-5.6-luna`, `medium` | Быстрый черновик по качественным субтитрам или готовой транскрибации | Не используйте по умолчанию при сложном разделении говорящих, плохом звуке или высокой цене ошибки. |

Используйте Sol с `xhigh`, если встреча длинная, качество звука низкое, участников много, источники противоречат друг другу или итоговая документация особенно важна. `max` стоит включать только тогда, когда ваша собственная проверка показывает измеримое улучшение: более высокий effort увеличивает стоимость и время ответа, но не гарантирует лучший результат.

Для короткой встречи с качественными субтитрами и заранее известными участниками сравните `sol/medium` и `sol/high`. OpenAI рекомендует начинать с `medium` как сбалансированного режима и увеличивать effort только тогда, когда проверка на типичных примерах показывает рост качества.

Эти настройки влияют на рассуждение, согласование источников и суммаризацию. Они не добавляют поддержку аудио или видео в среду, которая не умеет читать медиафайлы.

При смене актуального семейства моделей сверяйтесь с [рекомендациями OpenAI по выбору модели](https://developers.openai.com/api/docs/guides/latest-model).
